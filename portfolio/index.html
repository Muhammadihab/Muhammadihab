Most small shops in Egypt sell through WhatsApp. Customers ask "how much?", the message sinks under forty others, and nobody follows up.

Zaboon logs every customer who asks, where they came from, and when someone should call them back. The owner opens it in the morning and sees who to call today, the sales pipeline, money still owed, and which channel actually brings customers.

04 / before you see it

What I attack in every app before I hand it over.

Open each one. This is the short version of the list, written for people who don't do security for a living.

  1. I unpack my own release build the way an attacker would and look for API keys, database URLs and anything else that shouldn't ship. Release builds are obfuscated with --obfuscate --split-debug-info.

  2. The classic bug: change /orders/1041 to /orders/1042 and get someone else's order. I try it on every endpoint. The server checks who's asking, not just whether they're logged in.

  3. Tokens go into the platform's secure storage (Keychain / Keystore), not plain preferences. If the phone is lost, nothing useful is lying around in a file.

  4. Hiding the "delete" button from a technician is design, not security. Every role is enforced on the server, so calling the API directly gets the same "no".

  5. HTTPS everywhere, and certificate pinning when the data is worth intercepting. I put the app behind a proxy and watch what it actually sends.

  6. Who changed a price, who deleted an invoice, and when. The log is kept where users, including admins, can read it but can't edit it.

  7. Negative quantities, a 10,000-character name, a script inside a note field. Users will do all of it by accident. I do it first, on purpose.
